# AI Integration: where to customize

**Live app:** <https://aiskillmatrix.up.railway.app/> (sign-in required; accounts are created by an administrator).

All model-related code lives in **`backend/app/ai/`**. The rest of the app never imports OpenAI, LangChain or Chroma directly; it calls the small interfaces in this folder. The same map is shown live in the app under **AI integration** (sidebar), which reports which components are configured. It never shows secret values.

> **Secrets:** nothing is hardcoded. Set keys as environment variables or in your platform's secret store (Docker secrets, Vercel/Railway/Render env, Kubernetes Secrets, ...). For local work copy `.env.example` to `.env` (git-ignored).

## Behaviour without AI configured

| Capability | With `OPENAI_API_KEY` | Without |
|---|---|---|
| Project demand → required skills | LLM extraction (`ai/tasks.py`) | Keyword matching against the taxonomy; you edit the result anyway |
| Skill standardization | override → exact/alias → fuzzy → semantic (top 5 by embedding) → model pick: the LLM by default, or Jev with `STANDARDIZE_MATCHER=jev` and `TYPESAFE_API_KEY` (falls back to the LLM if Jev fails); only if the best embedding match scores at least `STANDARDIZE_MODEL_MIN_SIMILARITY`, default 0.5; skills whose names appear inside the phrase are always offered to the model as candidates). Only exact matches and earlier human decisions are applied automatically | exact → fuzzy → placeholder-embedding match → flagged for review |
| Staffing | complementary team (each member adds skills the team lacks); deterministic skill and role checks plus Chroma entity retrieval, reordered by a local FlashRank cross-encoder, rank candidates; study plans for skills nobody has | same, with **placeholder hashing embeddings** (lexical only) |
| Learning path | LLM-written Markdown from the gap + courses and videos (catalog, Microsoft Learn, YouTube) that Jev has checked are relevant | Template Markdown plan (same Jev-checked courses) |
| Free-text PDF extraction | LLM | Only tables and `Name: …` style PDFs |

Responses say which mode produced them (`mode`: `llm` / `heuristic` / `template`), and the UI shows it.

**Jev** decisions need `TYPESAFE_API_KEY`, independently of `OPENAI_API_KEY`. Without the Jev key, **learning plans show no course links** (every course must pass Jev's relevance check, and unverified courses are never recommended); gap risk then uses the LLM and then the formula, and standardization uses the LLM or the semantic/review fallback.

## Suggested order

1. Set `OPENAI_API_KEY` → check the **AI integration** page → re-upload or press **Re-index vectors**.
2. Tune `prompts.py` (especially `LEARNING_PLAN_*` and `REQUIREMENTS_*`).
3. Add Redis (`REDIS_URL`) and tracing keys.
4. Fill `course_catalog.csv`, set `YOUTUBE_API_KEY`, `TYPESAFE_API_KEY` (sensitive-data guardrail) and `GUARDRAILS_PROVIDER` (`both` for Guardrails AI and NeMo).
5. Evaluate with RAGAS, then consider fine-tuning on reviewed mappings.

## Production on Railway

Two services (backend with a volume at `/app/data`, frontend), deployed from a private GitHub repo with the Dockerfiles in `backend/` and `frontend/`. The backend runs as **one instance** because background jobs, agent runs and the AI rate-limit counters live in its memory. Set `AUTH_COOKIE_SECURE=true`, `EVAL_LOG_ENABLED=false`, `HF_HOME=/app/data/hf_cache` and all keys as service variables, never in the repo. Production installs `requirements.txt` (pinned by `requirements.lock`); `ragas` is only in `requirements-eval.txt`. Health check: `GET /api/health`. The frontend proxies `/api/*` to the backend; `BACKEND_URL` is read at build time. Keep `AUTH_SECRET` set: without it every restart signs everyone out. Step-by-step: `RAILWAY_DEPLOY.md`.

## Sign-in and sessions

**One session per user.** Each account can be signed in on one device at a time. Signing in somewhere else ends the earlier session (newest login wins), so nobody is locked out by a browser they forgot to log out of. Sessions are stored in the `user_sessions` table (`services/auth.py`, `routers/auth.py`); the cookie (`sm_session`) is signed with `AUTH_SECRET` and carries the session id, and every request checks that the session is still open. A partial unique index makes the database itself refuse a second open session for the same user.

**When a session ends**, the next request returns 401 with the reason, and the login page shows it once:

| Cause | Message on the login page |
|---|---|
| The account signed in on another device | You were signed out because your account was signed in on another device. |
| An admin ended the session | An administrator ended your session. Please sign in again. |
| An admin changed the password or role, or disabled the account | Your account was changed by an administrator. Please sign in again. |
| `SESSION_HOURS` (default 12) passed | Your session expired. Please sign in again. |
| The user logged out | None in the tab where they logged out; another open tab shows: You signed out. Please sign in again. |

**Log out** ends the session on the server, not only in the browser, so a copied cookie stops working at once. With one session per user, Log out also means "log out everywhere".

**Who sees sessions.** Each user sees their own session under their name in the sidebar ("Signed in … · Chrome on macOS"). The admin sees every open session on **Users & audit log → Active sessions** (user, role, device, signed-in time, last activity) and can sign anyone out; this is recorded in the audit log (`session_ended_by_admin`), as is a login that replaced another session (`session_replaced`). Endpoints: `GET /api/auth/me` (includes `session`), `GET /api/auth/sessions` and `POST /api/auth/sessions/{id}/end` (admin only).

**What is stored per session:** a short device label (browser and operating system, e.g. "Chrome on macOS"), the sign-in time, the last activity (updated at most once a minute) and the expiry, all in UTC. The raw User-Agent and the IP address are not stored.

**After deploying this change**, everyone has to sign in once more: cookies from before it carry no session id.

**Login lock-out.** 5 wrong passwords within 15 minutes lock that username for 15 minutes, even for the right password (`LOCK_AFTER`, `LOCK_WINDOW_MINUTES`, `LOCK_MINUTES` in `services/auth.py`). The count is stored in the `login_lockouts` table, so a restart does not clear it, and names that have no account are counted the same way. A successful sign-in clears the count. The admin sees locked usernames on **Users & audit log → Locked sign-ins** and can unlock them (`GET /api/auth/lockouts`, `POST /api/auth/lockouts/unlock`); locks and unlocks are in the audit log (`account_locked`, `account_unlocked`).

**Approvals are decided once.** Deciding a proposal first claims it (`pending` → `deciding`) and only the request that wins the claim applies it (`agents/proposals.py`). Two people or tabs approving at the same moment apply the change once; the other gets "This proposal was already decided". If applying fails, the proposal goes back to `pending`, and proposals left in `deciding` by a restart are returned to the queue at start-up.

## Access limits and errors

**Who may change shared data.** Adding or changing taxonomy skills (`POST /api/taxonomy`) and approving or dismissing skills that projects asked for (`POST /api/skills/requested`): HR manager and admin. Re-indexing the vectors (`POST /api/admin/reindex`) and deleting all data: admin only. Every staff role can still read the taxonomy. The pages hide these buttons from other roles, and the server refuses them (403) either way.

**AI rate limit.** Each user may make at most `AI_MAX_REQUESTS_PER_HOUR` (default 60) requests per hour to the endpoints that can call the AI, counted together: project requirements, gaps and staffing, learning paths, the Learning Coach, PDF uploads and re-parses, imports, CV reading (staff and a member's own CV) and role matching (`deps.count_ai_request`). A request is counted only after the route's own quick checks pass, so a request refused for invalid data, a missing field, an unknown employee or a wrong file does not use up the allowance, and Excel uploads (which never call the AI) are not counted. A request that passes those checks is counted even if a guardrail then refuses it or the answer comes from the cache. Over the limit the request is refused with 429 and "You have reached the limit of 60 AI requests per hour. Try again in N minutes." The admin is not limited; `0` turns the limit off. Agent runs keep their own limit (`AGENT_MAX_RUNS_PER_HOUR`, default 30).

**Server errors.** An unexpected error is logged in full under a short reference, and people see "Something went wrong on our side. Reference: 7F3K2Q". Only the admin also sees the error text (with key-like text masked). Search the backend log for `ref 7F3K2Q` to find it. The same applies to agent runs that fail unexpectedly; their error text is also in the audit log (`agent_run_failed`).

**"Why this choice" in study plans** (also in staffing's study plans) is written by code from the chosen course's own fields and the computed plan (`learning.why_choice`), e.g. "A beginner course from Microsoft Learn (0.5 h) that fits the 30 h planned for this skill." The model no longer writes it; it only picks the courses and writes the practice task.

**"AI reviewer changed the draft" note** (Learning paths). A second model call reviews the planner's course picks. The note people see is written by code (`learning.describe_review`): it compares the draft with the courses the final plan actually uses and names them by title, e.g. "For LLMs & Prompt Engineering, I swapped the course "Introduction to generative AI for trainers" for "Introduction to prompt engineering with GitHub Copilot": it is shorter and closer to beginner level, so it fits the planned time." The model only supplies the short reason after the colon, which is dropped if it contains internal ids, field names, JSON or links; a change the app's own checks then overrode is not mentioned.

## Interface

**Light and dark mode.** The app follows the computer's setting by default. The **System / Light / Dark** switch in the top bar overrides it; the choice is remembered in this browser (`localStorage` key `sm-theme`) and applied before the first paint by a small script in `app/layout.tsx`, so the page never flashes the wrong theme.

**Sidebar.** The button at the top left hides or shows the sidebar on desktop, remembered in this browser (`sm-nav`). On screens narrower than 820px the sidebar is a drawer over the page; it closes on a tap outside, with Escape, or when the page changes.

**Look.** Neutral minimalist: Charcoal `#111827` and Off-White `#FAFAFA`, charcoal primary buttons (off-white in dark mode), flat surfaces with 1px borders, no gradients, drop shadows or emoji. Text uses the system font stack (SF Pro, Segoe UI, Roboto); skill-level numbers use the system monospace font so the matrix columns line up. All colours are CSS variables at the top of `frontend/app/globals.css`, with the dark values below them.

**Colours with a meaning**, each used for one thing only:

| Meaning | Colour | Where |
|---|---|---|
| Skill levels 1-4 | blue `#DBEAFE`, `#93C5FD`, `#2563EB`, `#1E3A8A` (same in both themes) | skill matrix cells and legend |
| Verified / covered | green `#22C55E` | status labels and alerts |
| Pending / at risk | amber `#EAB308` | status labels and alerts |
| Gap / attention | red `#EF4444`, shown as an outline on a Gap label | status labels and alerts |

The base status colours are used for dots, outlines and tints; text uses darker shades of the same hues because the base colours are too light to read as text on white. Every text and background pair was checked for WCAG AA contrast (4.5:1).

**Skill matrix.** Thin gridlines outline every cell, with the column lines running up into the skill names. An empty cell (skill not listed) is blank; an unrated skill shows a dashed `?`. On phones the name column is narrower and long names are shortened (the full name and roles are in the tooltip).

**Tab icon.** The sidebar logo is the browser-tab icon (`frontend/app/icon.svg`, picked up by Next.js automatically).
